## Data, hooks, effects, API and storage

- `client/src/lib/queryClient.ts:27–57` joins query-key segments with `/`, includes credentials, throws on non-OK status and directly parses JSON. Infinite staleness, no polling/focus refresh/retry remain the current policy. `server/routes.ts:190–201` returns loan plus borrowers, 404 for missing loan and 500 for exceptions. `server/storage.ts:4–24,105–116` uses seeded MemStorage, not the database adapter. `shared/schema.ts:20–65` supplies loan/borrower types; it does not validate the frontend's local form drafts.
- Page `formatCurrency` uses `parseFloat` and US locale two-decimal formatting (`loan-origination.tsx:18–21`), including existing partial-string/NaN behavior. Only displayed header amount and initial requested amount are formatted here. Header data, borrower form data, pricing product and fees are **not** a synchronized loan model. No section sends a loan-save HTTP request.
- Borrower, Details and Fees use component state/ref snapshots only; Collateral persists **subject address only** under `loan-subject-property:<loanId>`; product/term/lock expiration and evaluation data are local only. The subject-property loader accepts an object when each required address key is a string, retains extra properties, and silently falls back on malformed/unavailable storage (`CollateralContent.tsx:354–377`). Address save swallows storage failure while still updating local state/checklist (`:629–643`). No user-visible save error/loading state exists.
- `checklist-context.tsx:159–211,241–285,287–429` loads validated action statuses from `loan-checklist-statuses:<loanId>`, derives parent status (all complete, then blocked, re-fire, in-progress, not-started), persists after updates and remounts by loan key. `completeAction` also advances the next not-started action; full re-fire handling applies to configured document tasks. Missing action lookup returns not-started. `refireCompletedTask` changes only already-complete parent tasks. Origination relies on these distinctions.
- `loan-activity-context.tsx:46–99,119–170` validates/reconstitutes saved runtime entries, retains seeded activities, persists runtime entries under `loan-runtime-activity:<loanId>` and deduplicates by ID. A repeated rate-lock action does not replace its first recorded timestamp. `lib/loan-activity.ts:1–10` produces locale/timezone-dependent US display timestamps; tests assume their fixed runtime timezone.
- Reset Demo is shared: `ChecklistPanel.tsx:14–23` confirms, calls `resetDemoTasks`, resets runtime activities and collapses expansion. `checklist-context.tsx:363–401` removes package progress, resets disclosure history and broadcasts `demoResetVersion` on completion; errors can return/toast before that completion. `lib/closing-disclosure-history.ts:54–100` writes under an optional Web Lock and notifies local/storage subscribers with cleanup; checklist subscription `:251–270` distinguishes disclosure-only resets from broad reset signals. Origination effects respond to **nonzero reset version**, including on subsequent mounts, not solely to the click moment (ORIGINATION-003).
- Toast hooks/global toaster (`hooks/use-toast.ts:8–9,74–126,175–186`; `ui/toaster.tsx:12–102`, `ui/toast.tsx`) keep only one notification, remove dismissed notifications after 300ms, and clean up subscribers. Collateral title-review and first rate-lock completion supply information toasts with 6000ms duration and loan/borrower interpolation. Do not expose real record values in fixture evidence.
- App's shared `useGitHubSync` adds a cached `/api/github/conflicts` query regardless of selected page (`hooks/use-github-sync.ts:39–42`); admin sync-status query is gated by panel open (`GitHubSyncPanel.tsx:58–60`). These are not Origination form requests. Shared server sync internals and their tests remain lead-owned, not independent recommendations in this report.

## Individually approvable findings

### ORIGINATION-001 — Separate borrower presentation sections without changing their contracts

- **Priority / confidence / class:** P2 / high / behavior-preserving maintainability candidate; no measured performance claim.
- **Evidence:** `client/src/components/loan/BorrowerInformationContent.tsx:186–506,508–662,665–1164,1166–1238`.
- **Observed problem:** One 1,241-line module combines input primitives, static questionnaire presentations, fixture data and dual-borrower edit orchestration. Boundaries already exist as functions, but changes to a small personal-information behavior require navigating unrelated static form content. Similar edit controls elsewhere are not byte-identical and must not be merged indiscriminately.
- **Suggested internal change / benefit:** Mechanically move the three static questionnaire sections and their private display helpers into narrowly scoped borrower presentation modules; keep fixture values, personal-editor state/refs and mount placement unchanged. This makes review smaller without introducing a generic form framework.
- **Scope / consumers:** Borrower Information only; shared dropdown and other page field primitives explicitly excluded.
- **Preservation rationale:** Same component identities/order, JSX, disabled values, dollar prefix, labels, test IDs, CSS/classes, widths and tabs; no new data binding, validation or persistence.
- **Risk / dependencies / effort:** Medium risk of incidental markup/cascade/remount changes; requires ORIGINATION-002 characterization and a safe fixture environment; 0.5–1 day.
- **Verification:** Compare full DOM and screenshots before/after at 1440×900 and 390×844 with both borrowers, edit/read-only modes and lower questionnaire content. Exercise independent drafts across borrower tabs, Save/Discard and sidebar remount; assert no changes to disabled questionnaire controls or tab/heading names after field edits. Check keyboard order and native DOB behavior.
- **Decision:** Awaiting user approval.
